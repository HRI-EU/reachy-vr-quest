# Reachy Mini Quest Teleop

Minimal Unity project for sending Meta Quest head, body yaw, and hand-derived antenna commands to a Reachy Mini bridge over ZMQ.

This repository is intentionally small. It is split out from the broader MirrorSkinVR workspace and keeps only the Reachy Mini teleoperation path:

```text
Quest body/head/hand tracking -> Reachy payload builder -> ZMQ DEALER -> Reachy Mini ROUTER bridge
```

## Unity Version

Use Unity `6000.3.9f1`.

The first time you open the project, Unity will restore packages from `Packages/manifest.json`. NuGetForUnity then restores NetMQ from `Assets/packages.config`.

## Dependencies

Unity packages:

- Meta XR SDK `85.0.0`
- Meta XR Movement from `https://github.com/oculus-samples/Unity-Movement.git`
- Unity OpenXR and XR Management
- Newtonsoft JSON
- NuGetForUnity
- Unity Test Framework

NuGet packages restored into `Assets/Packages/`:

- `NetMQ 4.0.4.1`
- `AsyncIO 0.1.69`
- NetMQ transitive dependencies such as `NaCl.Net` and `System.ServiceModel.Primitives`

`Assets/Packages/` is ignored by git because it is generated by restore.

NetMQ is a hard runtime dependency. Restore the NuGet packages before compiling or entering Play Mode; without the NetMQ DLLs the project should fail to compile instead of running with a fake transport.

## Scene

Open:

```text
Assets/Scenes/ReachyMiniTeleop.unity
```

The scene has two provider options:

- `MockSkeletonProvider` is active by default. It generates a small animated head pose and hand pose so you can test the transport and payload without a headset.
- `QuestTrackingProvider_Template` is inactive by default. Enable it and assign real Quest camera/head/hand references when building for Quest.

The runtime object uses:

- `ReachyTeleopConfig`
- `ReachyHeadCommandPublisher`
- `ReachyZmqDealerClient`
- `DebugReachyPayloadLogger`

Default config:

- Endpoint: `tcp://localhost:40000`
- DEALER identity: `body`
- Send rate: `10 Hz`
- Body yaw limit: `45 degrees`
- Finger plane range: `90 degrees`
- Antenna max: `90 degrees`
- Left/right antenna inversion: enabled

## ZMQ Wire Format

Unity uses a DEALER socket and sends multipart messages compatible with the existing Python ROUTER bridge:

```text
[empty frame, JSON payload]
```

A ROUTER peer receives:

```text
[dealer identity, empty frame, JSON payload]
```

Heartbeat payload:

```json
{"type":"heartbeat"}
```

## Reachy Payload

Main command payload:

```json
{
  "body_yaw_degrees": -12.5,
  "head_position": { "x": 0.0, "y": 0.0, "z": 0.0 },
  "head_rotation": { "x": 0.0, "y": 0.0, "z": 0.0, "w": 1.0 },
  "antennas": { "right": 0.12, "left": -0.08 }
}
```

Coordinate convention:

- Unity input is RUF: x right, y up, z forward.
- Robot output is FLU: x forward, y left, z up.
- Position conversion is `(x, y, z) -> (z, -x, y)`.
- `head_rotation` is the Quest head rotation relative to the shoulder frame, converted to FLU.

## Mock Receiver

Install pyzmq if needed:

```bash
python -m pip install pyzmq
```

Run:

```bash
python Tools/mock_reachy_router.py --bind tcp://*:40000
```

Then enter Play Mode in Unity. You should see heartbeat and Reachy JSON payloads printed by the mock receiver.

If Unity cannot compile NetMQ references, restore NuGet packages from `Assets/packages.config` with NuGetForUnity before entering Play Mode.

## Quest Setup Notes

For a real Quest build:

1. Enable OpenXR in Project Settings.
2. Enable the Meta/OpenXR features required by Meta XR Movement body tracking.
3. In `ReachyMiniTeleop.unity`, disable `MockSkeletonProvider`.
4. Enable `QuestTrackingProvider_Template`.
5. Assign `CenterCamAnchor`, `CenterEyeFront`, `CenterEyeUp`, and optional hand skeleton references on `MetaBodySkeletonProvider`.
6. Set `ReachyHeadCommandPublisher.skeletonProviderBehaviour` to `MetaBodySkeletonProvider`.
7. Set `ReachyTeleopConfig.endpoint` to the Reachy bridge address, for example `tcp://192.168.1.20:40000`.

If the `MetaSourceDataProvider` component is missing after package restore, add it from the Meta XR Movement package to `QuestTrackingProvider_Template`.
